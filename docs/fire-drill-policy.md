# 消防演练台账：排期口径与合规依据

## 1. 结论：合规判定只采用「自然周期」一种口径

系统同时实现了两种排法，但分工固定：

| 口径 | 用途 | 判定效力 |
| --- | --- | --- |
| **自然周期**（年度／上下半年／季度／月度固定窗口） | 排计划、合规判定、检查缺口清单 | **唯一合规口径** |
| **滚动间隔**（以上次实际合格演练日为锚点，每满 N 个月） | 内部加严预警 | 仅供管理参考，**不改变合规结论** |

检查前缺口清单（`drills gaps`）只按自然窗口出具；滚动超期只出现在"加严预警"
分区，避免两种口径混用导致同一份台账得出两个结论。

## 2. 合规依据

1. **《中华人民共和国消防法》第十六条**：机关、团体、企业、事业等单位应当
   履行的消防安全职责包括"组织进行有针对性的消防演练"，监管按**年度**核查
   （一般单位至少每年一次）。
2. **《机关、团体、企业、事业单位消防安全管理规定》（公安部令第 61 号）
   第四十条**：消防安全重点单位应当按照灭火和应急疏散预案，**至少每半年**
   进行一次演练；其他单位至少每年组织一次演练。
3. 人员密集场所、校园幼托等场景的行业／地方规章普遍按**季度、月度**作更严
   规定，地方有更严要求的从严执行（系统支持按月度/双月/季度/4 月/半年/年
   六档配置自定义条目）。

这些条文的措辞是"每半年／每年**至少一次**"，行政检查的核查方式是看**每个
自然时段内是否至少完成一次**（如上半年 1/1–6/30 内有没有），而不是看距上次
执行是否滚动满 180 天。

> 具体适用以现行有效文本与属地消防救援机构要求为准；系统内置依据文本可在
> 建台账时按单位实际替换。

## 3. 为什么不选滚动间隔作为合规口径：跨年覆盖差异

以半年档、上次合格演练日 **2025-12-20** 为例（`drills compare --anchor
2025-12-20` 可复现）：

| 次数 | 自然周期到期日（窗口末日） | 滚动间隔到期日（锚点 +N×6 个月） |
| --- | --- | --- |
| 1 | 2026-06-30 | 2026-06-20 |
| 2 | 2026-12-31 | 2026-12-20 |
| 3 | 2027-06-30 | 2027-06-20 |
| 4 | 2027-12-31 | 2027-12-20 |

两种排法覆盖的月份集合不同：

- 滚动口径的锚点随执行日漂移，跨年时落点是"12 月→次年 6 月"，不与任何固定
  半年边界对齐；一旦某次提前或延后，锚点会持续漂移，最终可能出现"间隔都没
  超过 180 天左右，但某个自然半年内一次都没有"的举证困境；
- 自然口径给每个固定半年兜底，窗口边界、覆盖月份年年一致，与法规"每半年至少
  一次"的文本和检查口径直接对应，台账无需解释算法即可举证。

因此**自然周期为准、滚动只加严预警**：两次合格演练间隔超过档级月数时系统会
提示，但最终缺不缺口，仍看自然窗口内有没有一次合格演练。

## 4. 合格判定：真实联动动作 + 证据，缺一不可

一次演练尝试（attempt）必须同时满足才算合格、才能覆盖窗口：

1. 全部必选现场联动动作成功：报警联动、应急广播、联动切断 PCS、灭火装置到位
   （可按单位裁剪）。任一项失败或未回报，整次记为**失败**——失败记录完整
   保留（含失败动作、指挥人、备注），但**绝不计为已完成**；
2. 三类必需证据全部登记：演练方案、签到名册、现场影像（登记文件名与内容
   SHA-256，原件另行归档），证据不可重复登记、不可覆盖。

## 5. 补救规则

- 失败或漏做后，用 `drills remediate` 在**同一自然窗口内**追加补救计划并执行
  合格的，覆盖该窗口缺口；
- **原始计划永不被修改**：补救是独立追加的计划条目，带有
  `source_plan_id` 指回原计划，失败尝试也继续留在窗口记录里；
- 窗口关闭后才补做的，系统明确标注"跨窗口补救不回溯"：整改事实记录在案，
  但原窗口缺口保留，检查时单独列示。

## 6. 留痕与防篡改

所有要求、计划、尝试、证据、补救事件写入同一条只追加的 JSONL 流水
（`var/state/drills/drill-ledger-*.jsonl`），按追加顺序串 SHA-256 哈希链；
系统不提供任何修改或删除入口。`drills verify` 逐条重放校验，任何字节改写
都会断链暴露。

## 7. 命令速览

```bash
python -m batterystore drills init                    # 建台账（内置四档周期）
python -m batterystore drills add-requirement ...     # 登记本单位适用档级
python -m batterystore drills plan --as-of 2026-10-04 # 按自然周期排计划
python -m batterystore drills execute --plan ... \
    --actions alarm_linkage=ok evac_broadcast=ok pcs_trip=ok suppression_valve=fail
python -m batterystore drills evidence --attempt ...  # 登记证据（自动算哈希）
python -m batterystore drills remediate --plan ...    # 追加同窗口补救计划
python -m batterystore drills gaps                    # 检查前缺口清单（有缺口退出码 1）
python -m batterystore drills compare --anchor ...    # 并排对比两种排期
python -m batterystore drills verify                  # 哈希链完整性校验
```

所有子命令加 `--json` 输出机器可读结果（放在子命令名之后）。
